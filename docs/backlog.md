# バックログ（MVP範囲外・将来検討）

MVPの範囲外だが、将来やるべき/やるかもしれない項目の一覧。優先度が高そうなものは実装案まで書いている。
**ここに書いてあるものはまだ実装しない**（プロジェクトの標準どおり、新機能は着手前にPlanで合意してから）。

## 優先度が高そうなもの（実装案あり）

### 1. 問題の質チェック機構（一部実装済み）

**背景**: 問題は一から作成する方針に転換済み（`docs/decisions.md`参照）。ユーザーが「本質的に問題の質にこだわりたい」と明言しており、AIの助けを借りて作る場合でも生成物をそのまま信用しない仕組みが要る。

**実装済み**:
- `scripts/generate_problems.py`: 生成**時点**での構造検証（segments整合性・文字数範囲・単語数が目標帯内か・重複）。不合格は生成結果に含めない
- `scripts/judge_audio.py`: TTS音声の文字起こし一致チェック（客観的）＋`--deep`でアクセント・自然さの参考判定（主観・自己採点バイアスの可能性ありと明記済み）

**未実装（残課題）**:
- 上記2つのチェック結果は**その場で表示されるだけで、`problems.yaml`にもプロトタイプにも反映されない**。つまりNG判定が出ても出題され続ける
- `Problem`に`verified`フィールドを追加し、`judge_audio.py`がチェック結果を書き戻し、出題プールは`verified: true`のみに絞る、という提案が出ている（未着手）
- そもそも今のプロトタイプ(`prototype/app.js`)はまだ`data/problems.yaml`と接続されておらず、独自のダミーデータのまま

### 2. アクセス制限（認証もどき）

**背景**: Netlifyで公開すると、URLを知っていれば誰でもアクセスできる状態になる（Netlifyの無料枠には公式のパスワード保護機能がない — 確認済み、Pro以上の有料プラン限定）。

**選択肢**:
- **URLの推測されにくさに任せる（何もしない）**: 個人情報や決済情報を含まない練習アプリなので、実害は小さい。ランダムなURLをどこにも公開しなければ、現実的なリスクは低い。**MVP段階ではこれで十分というのが率直な意見**
- **`_headers`ファイルでBasic認証（無料、ただし要検証）**: Netlifyの`_headers`ファイルに`Basic-Auth`指定を書く手法が一部で紹介されているが、確実に機能するか未検証。試すならまず動作確認が必要
- **Netlify Pro（有料、月$19〜）の公式パスワード保護**: 一番確実だが、個人の練習アプリに月額課金してまで要るかは微妙

**提案**: 今は何もせず、気になり始めたら`_headers`のBasic認証を試す、程度で様子見でよいと思う。

### 3. 履歴・統計画面の本格版 — 実装済み

専用の統計画面、レベル別内訳、簡易ストリーク、苦手な問題TOP5、JSONエクスポート、すべて`prototype/`に実装済み。発展形の「苦手な問題を優先的に出題する」（セッションをまたぐ間隔反復）は別途設計が要る大きめの機能として、引き続き未着手。

## 却下・方針が確定した項目

- **音声認識による自動採点**: **却下で確定**（2026-07-27、ユーザー判断）。理由: 音声認識の精度に対する個人的な不満・ストレスがあり、あえて自己申告方式のままにする方針。今後この案を再提案しない

## 収益化（将来検討、実装はリリース前提が固まってから）

**方針**: 無料アプリ＋控えめな広告、課金で広告ゼロ（よくある「広告解除の買い切り課金」モデル）。収益は「申し訳ない程度に入れば嬉しい」くらいの温度感で、大きな収益化は狙わない。

- **広告の置き場所が重要**: リスニング・回答画面（練習ループの最中）には絶対に置かない。Part選択画面やセッションリザルト画面のような「区切り」のタイミングにバナー程度が妥当
- **広告SDK**: Google AdMob等（未選定）
- **広告解除**: サブスクではなく一回課金（StoreKitのIn-App Purchase）で十分な規模
- **アフィリエイト**: 技術的には可能（統計画面等に控えめな教材紹介リンク程度なら違和感なし）。優先度は広告解除課金より低い
- 直近のマイルストンがApp Store配信に確定した（`docs/decisions.md`参照）ため、**PWA向けのWeb決済(Stripe等)は検討不要**。AdMob(ネイティブSDK)＋StoreKit前提で設計する
- 実装はまだ早い。実際にストア公開する段になってから着手する
