# バックログ（MVP範囲外・将来検討）

MVPの範囲外だが、将来やるべき/やるかもしれない項目の一覧。優先度が高そうなものは実装案まで書いている。
**ここに書いてあるものはまだ実装しない**（プロジェクトの標準どおり、新機能は着手前にPlanで合意してから）。

## 優先度が高そうなもの（実装案あり）

### 1. 問題の質チェック機構

**背景**: 問題は一から作成する方針に転換済み（`docs/decisions.md`参照）。ユーザーが「本質的に問題の質にこだわりたい」と明言しており、AIの助けを借りて作る場合でも生成物をそのまま信用しない仕組みが要る。

**提案（段階的に）**:

1. **構造的な自動検証（コストゼロ、今すぐ作れる）**: `scripts/validate_problems.py`として、`data/problems.yaml`に対して以下をチェックし、違反があれば失敗させる（fail loudly）。
   - `script_segments`を結合すると`text`と一致するか（コピペミスの検出）
   - `char_count`が異常値でないか（例: 10〜200文字の範囲外は要確認）
   - 文末が適切な句読点で終わっているか
   - 完全一致・ほぼ一致の重複問題がないか
   - セグメント数が反復練習として不自然でないか（例: 2〜6個程度が目安）
   - Versant Repeating本来の趣旨に沿っているか（不自然に長い/短い、口語として不自然、等）は自動判定が難しいので次のステップへ

2. **LLM-as-judge（任意、少額のAPIコスト、コンテンツ作成時のみ実行）**: 新規問題ごとに「自然さ」「文法的正しさ」「難易度分類の妥当性」を別モデルに評価させ、閾値以下は自動却下ではなく**人間レビューへ回す**（誤判定で良い問題を消さないため）。

3. **手動スポットチェック**: コーパスが小規模（1バッチ16問程度）なので、レビュー用チェックリストを用意する程度で十分な可能性がある。

**次に決めること**: 問題をどう作るか（完全手動 / AI支援での下書き＋人手修正 / 自動生成＋人手承認）が決まらないと、2番目のステップの要否が変わる。ここは着手前に相談したい。

### 2. アクセス制限（認証もどき）

**背景**: Netlifyで公開すると、URLを知っていれば誰でもアクセスできる状態になる（Netlifyの無料枠には公式のパスワード保護機能がない — 確認済み、Pro以上の有料プラン限定）。

**選択肢**:
- **URLの推測されにくさに任せる（何もしない）**: 個人情報や決済情報を含まない練習アプリなので、実害は小さい。ランダムなURLをどこにも公開しなければ、現実的なリスクは低い。**MVP段階ではこれで十分というのが率直な意見**
- **`_headers`ファイルでBasic認証（無料、ただし要検証）**: Netlifyの`_headers`ファイルに`Basic-Auth`指定を書く手法が一部で紹介されているが、確実に機能するか未検証。試すならまず動作確認が必要
- **Netlify Pro（有料、月$19〜）の公式パスワード保護**: 一番確実だが、個人の練習アプリに月額課金してまで要るかは微妙

**提案**: 今は何もせず、気になり始めたら`_headers`のBasic認証を試す、程度で様子見でよいと思う。

### 3. 履歴・統計画面の本格版

**背景**: 今夜、選択画面に1行だけ「これまでの記録」を追加した(累計問題数・正答率)。これをちゃんとした画面に育てる余地がある。

**提案**:
- 専用の「統計」画面を追加（Part選択画面などから遷移）
- 内容案: 累計正答率、総練習回数、レベル別内訳、直近の練習日（簡易ストリーク）
- 「苦手な問題」表示: 正答率が低い問題を一覧化（今のスキーマ`{attempts, correct}`があれば計算可能）
- **バックアップ/エクスポート**: 今はlocalStorageのみなので、ブラウザのデータを消すと記録が消える。JSON書き出しボタンを用意しておくと安全網になる
- 発展形として「苦手な問題を優先的に出題する」（セッションをまたぐ間隔反復）も考えられるが、これは別途設計が要る大きめの機能
